# polywars

RTS game where the commander is a hero unit - micro your commander with six weapons, wire pylons to power, and claim metal spots.

**Author:** goddot

Full design: [docs/DESIGN.md](docs/DESIGN.md).

```
dist/   build output (.sdz game, .sd7 map)        docs/   design + example start script
game/   the game archive root (becomes the .sdz)   map/    mapinfo.lua + generated map sources
tools/  gen_map.py, gen_assets.py, pngutil.py      build.py
```

## Build
```
python3 build.py              # game + map
python3 build.py --game       # dist/PylonWars-0.6.2.sdz  (no dependencies)
python3 build.py --map        # dist/polycity.sd7
python3 build.py --install    # copy into ~/.spring (or %USERPROFILE%/Documents/My Games/Spring, or $SPRING_DATADIR)
python3 build.py --assets     # regenerate placeholder models/textures/pics
```
The `.sdz` needs only Python 3. The `.sd7` additionally needs:
1. a **map compiler** on PATH (`springmapconvng`, `pymapconv` or `mapconv`), or set
   `MAPCONV="<cmd> -o {smf} -t {tex} -a {height} -m {metal} -n {minh} -x {maxh}"` to match your tool's flags
   (the default flags are my best recollection of the common ones; check your tool's `--help`);
2. 7-Zip: `pip install py7zr` or a `7z`/`7za` binary.

Without a compiler, `build.py --map` still writes the PNG sources to `map/build/src/`; compile them, put
`polycity.smf` + `polycity.smt` in `map/prebuilt/maps/` and run `python3 build.py --map --no-convert`.

## Play
`spring docs/example_startscript.txt` (edit names/ports first). Select the commander, then
* **Z X C V B N** or click the bar: toggle weapon slots 1-6 (rings on the ground show enabled ranges)
* build Pylon + Generator near a metal spot, then the Weapon Factory (the overlay shows why a spot is invalid).

## Changelog (engine-tested fixes)
- Added `LuaRules/main.lua` + `draw.lua` (without them no gadget loads, so no commander spawned).
- Start scripts must use full archive names: `polywars 0.6.2`, `polycity 1.0`.
- Unit `weapons` entries use `name =` (this engine ignores `def =`).
- Lua unit scripts (`scripts/`) + shipped `unit_script.lua` gadget: required for building/aiming.
- Factories need `isfactory`, a yardmap and a yard-opening `Activate`; all structures get a yardmap.
- Added death explosions (`weapons/common.lua`) and a built-in skirmish bot (`pw_bot.lua`, disable with modoption `pwbot=0`).
- Factory footprint reduced from 5x5 (80 elmos, the whole metal spot) to 4x4 (64 elmos); the metal check now
  accepts a factory whose footprint touches any metal cell; generated map metal spots are 7x7 px (112 elmos).
  Re-run `python3 build.py` to regenerate/recompile the map if you use the generator.

## v0.3.2
* "Can only be built on a metal spot" fix: if the compiled map's metal layer is empty/shifted, placement (and the bot,
  and the overlay) fall back to the configured Pylon City spots in `pw_config.lua` (`PYLON_CITY_SPOTS`). Real metal cells still count.
  On a map with no metal at all and no configured spots the restriction is lifted instead of blocking every build.
* **Power wires**: `LuaRules/Gadgets/pw_wires.lua` draws pylon-to-pylon links and wires from pylons to generators (yellow),
  siphons/turrets/factories (green); a red stub marks a powerless building. Pulses travel along live wires.
* **Power grid** (`pw_power_grid.lua`): siphons, turrets and factories are shut down (stunned) while no finished pylon of
  their team is within `PYLON_RANGE`, and restart when a pylon is rebuilt. Messages tell the team what happened.
* Removed the deprecated `autoShowMetal` from `map/mapinfo.lua` (recompile the map to drop the warning).

## v0.4.0 - sounds
* 17 synthetic placeholder sound effects in `game/sounds/` (generated by `python3 tools/gen_sounds.py`, no external assets),
  registered in `game/gamedata/sounds.lua` (`SoundItems`, with per-sound gain, pitch variation and max concurrency).
* Weapons: light/heavy laser, autocannon, cannon and mortar fire sounds plus impact/explosion hits (chosen automatically
  from each weapon's type, range, reload and area of effect at the end of `weapons/aegis.lua` / `vanta.lua`).
* Death explosions: small / medium / large (units / structures / commanders).
* Units: select, order-acknowledge and "can't" sounds.
* Events (`pw_sounds.lua`, other gadgets call `GG.PW_Sound`): building complete, blink (both ends), veteran level-up,
  power lost / restored. Team feedback sounds are heard only by the owning team; world sounds need line of sight.
* To replace a sound, drop a WAV/OGG with the same name into `game/sounds/` and rebuild.

## v0.4.1 - wires fix
The power-wire overlay is now an **unsynced gadget** (`LuaRules/Gadgets/pw_wires.lua`) instead of a LuaUI widget, so it
loads whenever the game rules do. Always drawn on top (no depth test, glow + pulses), from each building's centre.
Colours: cyan pylon<->pylon, yellow generators, green siphons/turrets/factories, red stub = no power.
`/pw_wires` toggles it. On load it prints "[Pylon Wars] power wires loaded" in the console/infolog.

## v0.5.0 - pylon light and sensor range
* Pylons **emit light**: an additive pool of light on the ground (radius 210) plus a pulsing, camera-facing halo on the
  pylon head. Aegis glows blue-white, Vanta orange-red; unfinished pylons glow dimly. (Drawn with additive blending
  because the engine's dynamic lights need deferred rendering, which is off by default.)
* **Sensor range** rings: every finished pylon shows its sight radius (450); select a pylon to also see its radar
  radius (Aegis 900, Vanta 800). Pylons now have 450 sight so a pylon network doubles as a vision net.
* `/pw_glow` toggles the light, `/pw_range` toggles the rings. Code: `LuaRules/Gadgets/pw_pylon_glow.lua`.

## v0.6.0 - more units and structures
**Structures** (per faction; commander and constructor can build them): 
* *Repair Beacon* - pylon-powered, heals friendly units and buildings within 280 elmos at 20 hp/s for a little energy.
* *Sensor Mast* - pylon-powered, sight 800 / radar 1700 (Aegis) or 750 / 1500 (Vanta); cheap and fragile.
* *Barrier* - cheap, very tough wall (3000 / 4000 hp), no power needed; shape the city's streets.
* *Obelisk* (Aegis, 720-range beam) / *Mortar Battery* (Vanta, 780-range artillery) - pylon-powered long-range towers.

**Units** (from the weapon factory): *Scout* / *Raider* (very fast, cheap), *Striker* / *Bruiser* (mid tier),
and the **Constructor** (mobile builder: pylons, generators, siphons, turrets, beacons, masts, barriers, artillery).

All pylon-powered structures obey the power grid (placement needs a finished pylon in range; no pylon = shut down) and
show wires. Every new unit/structure has its own placeholder model and build picture (`tools/gen_assets.py`).
The earlier Warden/Juggernaut/turrets and the siphons now also have their own models instead of reusing others.
The bot builds a beacon and artillery at home and only mass-produces armed units.

## v0.6.1 - scarcer energy, flickering lights
* Generators now make less energy: Aegis 45 -> **28**/s, Vanta 40 -> **25**/s. Energy is a real constraint again
  (commander weapons, blink and repair beacons all draw on it).
* **Low-energy flicker**: when a team's energy store drops below 25 % its pylon lights and power wires dim and flicker,
  with random blackout flashes that get more frequent as the store empties (about 11 % of the time at 20 %, ~50 % near 0).
  The curve lives in `LuaRules/Headers/pw_lightfx.lua` (`LOW`, brightness model) and is shared by `pw_pylon_glow.lua` and `pw_wires.lua`.

## v0.6.2 - repair beacon crash fix
* **Fixed** `pw_repair.lua:23: attempt to index field 'beacons' (a nil value)` (thrown every 15 frames): `pw_config.lua`
  had no `beacons` set and no `BEACON_RADIUS`. Both are now defined, and the gadget caches beacon def IDs instead of
  scanning every unit by name.
* Beacons now heal **allied** units (not just the owner's team) and ignore dead/unpowered ones.
* Repair beacons, sensor masts and heavy towers (Obelisk / Mortar Battery) are now actually pylon-powered like their
  descriptions say: shut down without a pylon (`pw_power_grid`), only placeable inside the network (`pw_factory_rules`),
  drawn on the wire overlay, previewed by the placement widget (new `cfg.beacons/masts/obelisks`, `placement.Sets().consumers`).
* Removed the deprecated `Spring.GetUnitCommands(id, 0)` calls in the bot (uses `GetUnitCommandCount`).
* Bot builds a repair beacon at its home base.
